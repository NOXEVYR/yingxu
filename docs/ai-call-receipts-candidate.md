# 工具结果与原轮成果关联候选

构建：0.4.27/calls.3；独立源码候选，未安装、未打包、未发布。

## 使用流程

在 AI 协作的原任务轮次展开“工具调用”。成功调用的“关联本轮成果”入口默认收起；用户点击“刷新候选与关联”时，读取该调用的关联历史和该轮生成目录里的文件。选择工具结果及文件，再明确确认关联。成功后原任务的成果列表刷新，预览和审核继续使用原有流程。

该入口不下载、不启动生成、不增加媒体库，也不会自动采用成果。工具仅返回结果描述时，用户仍需先把实际文件放入本轮生成目录。真实服务适配与传输不是本次已完成的范围。

工具提供 SHA-256 时必须与实际文件一致；提供大小时也必须一致。没有 SHA-256 时必须确认手动关联，账本长期保留“来源未核验”，不能把本地文件完整性核验写成服务来源证明。前一阶段 LibTV 的真实配音验证是主代理通过服务工具生成后手动接收，不能据此宣称 YingXu 已内置 LibTV 适配。

## 持久记录与失败恢复

工具成功结果根据整份结果快照、结果位置和结果内容派生稳定 `result_id`。重名和相同资源 ID 不合并不同结果位置。原始尝试结果不被关联操作改写。

关联表先保存原任务/轮次/调用、结果快照、文件摘要及服务端派生收件计划，再调用原 AIReceiptService 收件，最后保存原 receipt/artifact 标识。文件仍在原位置，项目 items 与审核记录继续复用。所有权检查适用于新建、历史重放和恢复；历史完成重放不要求最新轮次或可写任务。

收件完成但关联回执提交中断时，核对原请求可以补齐账本，并保持同一个成果，即使之后创建新轮次或明确完成任务。收件尚未完成的恢复必须仍满足原收件的最新可写轮次条件。原收件失败或中断时保存错误，只有用户明确使用新请求键才重试，不把断连当作失败后自动重复。

浏览器暂时断连时保留原请求键、结果和文件选择；“核对本次关联”使用冻结请求，修改界面选择不会改变未知请求。切换任务或项目后的迟到回执只更新原范围记录，不能绘制其他项目；忙碌状态持续保护退出与迁移。父任务刷新失败时关联保持已完成，提示刷新任务，不重新收件。

## API 与限制

工作台同源会话入口：

- `GET /api/ai-tasks/{task}/runs/{run}/calls/{attempt}/receipts`
- `GET /api/ai-tasks/{task}/runs/{run}/calls/{attempt}/receipts/{id}`
- `POST /api/ai-tasks/{task}/runs/{run}/calls/{attempt}/receipts`
- `POST /api/ai-tasks/{task}/runs/{run}/calls/{attempt}/receipts/{id}/resume`，请求体必须为空对象。

新建请求含 `idempotency_key`、`result_id`、`relative_path`，可带 `role`、`confirmed_unverified_source`。不接受绝对路径、任意已有 item ID 或外部 URL。MCP Bearer 不能读取或写入该私有工作台接口；现有七个 MCP 工具不变。

只允许本轮受控生成目录内可管理普通文件；私密目录、配置、越界路径与链接拒绝。每个文件先检查大小再流式核验，最多512MiB，不缓存全文件；更大文件继续使用原收件流程。每轮最多200条关联，全库5000条记录。列表显式读取，无 watcher、后台扫描或空闲轮询。没有新增运行依赖。

## 验证边界

合成 HTTP 服务和隔离数据库验证重复请求、并发、跨任务拒绝、摘要与大小不符、手动来源确认、实际 TCP 回复丢失、提交前后中断、服务重建、旧轮恢复、收件错误、MCP/迁移权限和不可变意图。

前端 VM 测试验证按需读取、原请求冻结、未保存保护、跨页迟到响应、原关联恢复及父任务刷新。它们不等同于实际桌面渲染、真实 AI 客户端、付费媒体生成、Windows/macOS 原生或用户听感验收。本阶段未替换正式程序或发布包。
