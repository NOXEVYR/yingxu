# Stage G：原轮Hub成果与本地文件关联

这是独立源码候选，基于已封存Stage E复制推进。没有更新正式安装、版本号或下载页，没有上传或发布；原Stage E/F、项目、技能和私有授权保持原样。

## 用户操作

在AI协作的“工具调用 → 通过曜核调用”中，对工作端已报告完成、具有完整结果清单摘要的原执行，展开“关联本轮成果”。点击刷新后，明确选择原执行的结果和已放入原轮生成目录的文件，再确认关联。默认收起，不会自动读取文件列表、下载远端媒体、派单、生成或审核。

界面标注“已关联 · 待审核”。关联复用原AIReceiptService和既有素材条目，不创建第二套媒体库。实际文件SHA必须匹配工作端声明；缺少SHA的Hub成果不开放此入口。原有人工交接与直接工具收件保留。

## 固定绑定和持久恢复

- 关联原project/task/run/binding/request/execution/result_id、整份results manifest摘要及本轮相对文件名。Unicode结果ID保留精确字节，不做NFC/NFD归一化。
- 先保存不可变关联意图，再进行原收件，最后记录原receipt/artifact。响应丢失、HTTP 5xx或回执作用域不符时保留原键，只有用户点击“核对原关联”才恢复，不建立新键。
- 已存在pending记录只恢复原关联ID。完成收件之后的关联提交缺口可以核对原完成成果；旧轮尚未完成的收件、新关联或新增文件不能越过最新轮次。
- 较早发起的读取不得覆盖刚完成的关联。同一原轮界面重挂后，完成回执刷新当前同轮父任务；换轮后的迟到结果不会刷新或加入新轮。

## 文件和生命周期边界

仅原轮受控目录的已有普通文件，拒私密路径、链接、重解析点、硬链接、摘要/大小不符和文件身份替换。不解释远端locator，不下载URL，不接收worker/owner授权。hash在数据库写事务之外；限制单文件512MiB、每轮200关联、全库5000关联。

写操作复用Hub本地在途操作和原任务锁，纳入更新、迁移与退出保护；未保存文稿先拦截。没有新增常驻服务、空闲轮询、文件watcher、SDK、模型或字体。MCP仍保持原七个只读工具，不从此入口开放派单或收件写权限。

## 验证边界

定向测试覆盖原绑定、原轮、重复收件、部分提交、摘要/Unicode/文件身份、授权、更新迁移和真实工作台HTTP路由。无头浏览器检查实际DOM、父子忙碌、原键恢复、晚到刷新、同轮重绘与跨轮迟到响应，使用合成API和项目，不能据此宣布正式桌面或真实模型验收。

整套回归和候选源文件的摘要由上级test-evidence保存。封存脚本只允许基线源文件和明确新增文件，不包含回归留下的合成数据库/授权、私有runtime或用户数据。

Stage F已经完成一次独立的真实无模型PNG闭环，证据另留档；本Stage G没有再次执行原生生成。跨进程媒体读取接口、视频/音乐/云端模型、正式桌面替换和发布仍需分别验证。
