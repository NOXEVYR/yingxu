# 曜核只读选型适配候选

2026-10-02，0.4.27/calls.2。保留映序任务、冻结轮次、固定技能、人工交接、收件与审核，在原默认收起工具区增加一个可明确选择的连接协议。没有创建新的生成任务账本、常驻页面或服务。

## 已实现

保存连接时显式选择 `aihub-interop/1`，填写本机回环地址；不固定端口、不启动、扫描或发现服务。保存不联网，“检查连接”只读 `GET /api/interop/describe`。`AIHubProvider` 仅允许这条出口与单能力 `GET /api/interop/capability-snapshot`；提交、原生任务查询和取消均拒绝。原 `yingxu-http-v1` 直接路径继续独立运行。

当前选型先从曜核复制明确的 capability ID，点击“保存本轮选型”。没有能力浏览目录或自动选型。后台先核对检查时的身份/工作区绑定，再以原 connection_revision、workspace_root 读取单能力快照。返回对象、响应原 UTF-8 字节、SHA-256、本机连接修订、输入摘要保存于原冻结轮次。响应原文不重序列化后冒充原响应，声明 text 的 UTF-8 bytes/sha256 与 parsed 另外核对；来源是 stored_normalized_declaration，不是最初发布字节。

新表 `ai_capability_selections` 保存不可变选择，UPDATE 触发器禁止覆盖。去重使用本任务轮次 + 自己的 idempotency_key + 完整选型请求；不使用曜核 snapshot_id 作为唯一身份。响应丢失后同键读取原结果，不重新建立选型；成功后如需新版，用户明确“建立新选型”。读取与重启不联网，核对变化不更新旧快照或心跳证据。

“核对声明变化”读取当前描述并核对原实例、工作区、本机连接修订与曜核连接修订，再带原 expected_declaration_sha256 读快照。404、409、413、422、503按明确边界失败，旧记录仍在；不静默换新版本。读取期间连接配置变化也不能假报匹配。

## 执行边界

当前曜核是 harness_queue：需要工作端领取，按工作端类型路由，派单没有声明摘要 CAS。保存或核对选型不会调用 capability_dispatch、执行模型、创建任务、读取报告或收录媒体。前后端均保留 execution_allowed=false、dispatch_version_locked=false、actual_invocation=unverified；心跳不是实际执行证据。已登记启用、未登记、登记不可用分别保留，nullable状态不被伪装成启用。

选型服务不是完整输入传输、基础生成适配或媒体闭环。目标、验收、输入文件、固定技能及预算的完整传输仍需下一阶段实现；工具完成、成果落盘、映序收件、人工审核继续分开。

## 范围与成本

- 仅Python标准库；无新运行依赖、模型、字体或下载。
- 每次请求2秒总截止时间，无代理、重定向、端口扫描；正文128KiB，含头部及分块结构总预算另加8KiB；声明32KiB。
- 每轮最多24个快照、全库256个，原响应累计最多16MiB。达到上限保留原记录并明确拒绝，不自动删历史。
- 中文按UTF-8字节检查，允许来源规范的CRLF；拒绝秘密字段、可识别凭据及认证/签名URL。路径只作为来源绑定信息，不解析或打开来源路径。
- 工作台全部私有读取与操作继续要求原会话令牌；MCP Bearer不能读/写选型，原只读七工具不变。写门禁、迁移和退出保护复用原流程。
- 默认收起无网络；按本项目任务轮次保存草稿/原请求，迟到返回不会绘制另一项目；输入框不会随每个字符重建。

## 工作台接口

`/api/ai-tasks/{task}/runs/{run}/capability-selections`：GET有界列表（limit1–24、offset0–256）；POST显式保存，字段为 connection_id、connection_revision、source_connection_revision、capability_id、idempotency_key。

同路径 `/{selection}`：GET原完整选型；`/{selection}/verify`：POST空对象核对，不替换原记录。没有调用或取消动作，也不是任意地址代理。
