# 映序 0.4.36 / frames.4 · Windows 逐帧

本次在 0.4.35 / frames.3 源码基础上补齐 Windows 运行库与逐帧处理，供本地桌面版使用。公开下载入口仅在实际发布并回检后更新。

## 使用

1. 在映序打开视频，进入工作台的“审片与粗剪”。快速播放器可通过顶部“在工作台打开”进入。
2. 点击“后台建立真实帧索引”。此时仍可播放、暂停、跳转、调整倍速和记录审片；索引完成不会突然暂停视频。
3. 点击“暂停并检查第 0 帧”，或输入从 0 开始的帧号并定位。点击上一帧/下一帧，或在视频区域聚焦后按 `,` / `.` 逐帧检查；输入框保留自身键盘行为。
4. “继续播放（近似定位）”返回普通视频，并保留已建立的索引。“关闭索引与检查”取消任务、释放索引与静帧缓存。
5. 可将当前帧分别设为首帧、尾帧，导出包含两端的严格源帧范围。导出后会复验 RGB 像素、帧数和有理数 PTS。

严格帧导出使用 FFV1 MKV/NUT，**仅视频、不含音频**；快速播放器不保证支持该编码。需要声音时使用原有按时间裁切。浏览器视频定位属于近似定位；严格静帧检查以完整顺序解码得到的展示序号为准，不按平均帧率猜测。末帧持续时长仍由容器处理。

## Windows 实现

- 同一锁定 FFmpeg 9.0.1 档案同时提供 ffmpeg.exe 与 ffprobe.exe，运行时校验实际包内文件；缺失或变更时明确提示，不调用电脑中其他 FFmpeg。
- 原锁定 FFmpeg 下载地址失效，改用作者的 [GitHub 9.0.1 附件](https://github.com/GyanD/codexffmpeg/releases/tag/9.0.1)。档案字节数 `111253802` 和 SHA-256 `fec81ae03971d9dd4be3ebe02e263bd2ec1d789483f931bdba5f5715e65da2e9` 保持不变。
- 源文件缓存使用 Windows 文件 ChangeTime 识别同尺寸且恢复 mtime 的改写；无法取得该元数据时重新读取摘要。
- 工作进程隐藏控制台窗口，保留单任务工作队列及解码、滤镜、编码线程限额。
- 测试和构建使用独立临时数据、项目与合成视频；安装切换保留旧程序及应用数据备份。

## 验证入口

后端：`python -B -m unittest discover -s tests -v`，包括真实 CFR/VFR、旋转、重复 PTS、像素核验、导出、取消和文件失效回归。开发测试需将包内 FFmpeg 目录加入该测试进程的 PATH；产品运行不依赖系统 PATH。

前端：逐个运行 `tests/frontend_*.cjs`。跨功能串联检查为 `tests/test_stability_journey.py`，涵盖文稿编辑、改名、跨项目移动、回收恢复、迁移与重启。

原生：`python desktop/build.py --sdk-package <锁定 SDK> --output YingXu.exe --test`。最终 ZIP：`python tools/verify_release.py <Windows ZIP>`，核验清单与大小/摘要，并使用解压后的 Python、FFmpeg 和 ffprobe 进行帧检查和导出。

本次范围为 Windows x64。macOS 逐帧仍未开放；多屏、不同 DPI、物理音画同步和长期运行表现需在对应设备另行验收。
