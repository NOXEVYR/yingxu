# 工作台页面整理候选 · Stage J

这次先把 SKILL 库和 AI 协作页作为完整页面整理，再以两种导航方式使用同一套功能。原工作台也使用新的搜索、紧凑卡片和右侧工具区，不再保留一套完成度不同的旧页面。

| 页面 | 原工作台 | 聚焦工作台 | 共用内容 |
| --- | --- | --- | --- |
| 创作资源 | 固定资源导航 | 相同资源导航 | 原有资源、文档、画板与关联 |
| SKILL 库 | 范围、分类、标签在页面工具栏 | 相同入口放到左侧导航 | 列表内搜索、卡片/列表、来源、整理、收藏、绑定及框选 |
| AI 协作 | 左侧固定资源导航，任务列表在页面中 | 左侧切换为当前项目任务与工具导航 | 同一份任务、轮次、材料、交接、成果与审核记录 |

SKILL 搜索与顶部搜索共用查询值。按名称、用途说明、路径、个人标签和备注筛选已载入的数据；多个词需同时匹配。中文组合输入期间不发出查询，完成后防抖更新；不会因输入关键词扫描目录。旧后端需要请求时，保留输入节点，并拒绝旧查询响应。清除搜索只清除关键词，保留已选择的分类、标签与来源。

AI 协作中央用于任务、固定材料与成果审核。右侧“项目工具”在项目交接和 MCP 连接之间切换，面板高度有上限，长内容在内部滚动。窄窗口由“交接 / MCP”按钮展开，可以关闭或按 Esc 收起；输入法候选中的 Esc 不收起面板。两页签首次打开才挂载，随后保留各自草稿，切换模式和页签不重挂任务表单或正文编辑器。

刷新交接摘要只更新摘要、统计、文件路径和项目记录，不重画协作页面。响应必须仍属于原项目、原页面和原宿主；切走后的晚响应不会覆盖新项目。左侧任务重绘会恢复等价按钮的键盘焦点和滚动位置。任务分页保留在所属任务列表内，避免聚焦模式出现重复分页控件。

本轮不改变磁盘分类、技能固定版本、任务轮次及 MCP 只读协议。新增部分是原生 JavaScript/CSS，五个前端程序文件净增 21,207 字节（约 20.7 KiB）；没有新增 SDK、字库、模型、运行依赖或空闲扫描任务。尚未测量真实安装包与运行内存变化。

已验证：78 个前端测试文件（702 项，1 项跳过）、97 个后端测试模块（1,069 项，11 项跳过），最终执行项均通过；独立完整应用用合成数据通过 23 项界面检查，覆盖原/聚焦模式、1440 与 900 像素窗口、长面板滚动、搜索、中文输入法、页签草稿、刷新竞态和键盘任务切换。

前端跳过项是 Windows Chromium 命令行窗口无法缩到 480px 以下。后端跳过涉及符号链接权限、macOS 原生系统接口及未提供的更新助手运行库。首次整体后端运行达到测试 runner 的 360 秒超时，之后按模块完成全部检查；0 项测试的 incremental_support 仅为辅助模块。源码候选没有编译目录，原生版本检查改为显式读取已封存 Stage I 测试 EXE 的元数据，不执行它。Chrome 命令行测试曾因临时浏览器目录清理的 Windows EPERM 失败，受影响三项最终在 Edge 顺序复验通过；产品行为检查并非该清理错误。

这是独立源码候选，基于 Stage I 封存源码。正式安装、历史留档、用户项目和技能数据没有替换；未提交、上传或发布。完整应用截图来自隔离 HTTP 后台及自有隐藏浏览器，不能代表 Stage J 原生 EXE、真实生成流程或 Mac 已验收，也不据此标注稳定版。

源码与证据保存在上级目录。`run_layout_checks.py` 使用合成 HOME/临时目录运行既有测试，`verify_layout_render.cjs` 启动自有随机回环端口进行页面验收，`seal_layout_candidate.py` 生成来源清单、离线对比图和源码候选 ZIP。生成的合成数据库及浏览器资料留在测试证据区，不纳入源码 ZIP。
