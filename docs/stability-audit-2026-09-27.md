# 0.4.20 整体稳定性审查

审查时间：2026-09-27 至 2026-09-28。对象为 Windows 0.4.20 / startup.1 的共享源码及原生宿主；修复尚未作为新发行包安装或发布。

## 当前结论

**暂不将现有发行版标注为通过本轮整体验收的稳定版。** 本轮发现了真实的草稿、迁移身份及跨功能状态问题，已在源码中修复。自动化结果与尚未覆盖的环境分开记录；macOS 保持试用范围。

## 已修复的问题

| 问题 | 处理与回归 |
| --- | --- |
| 载入中或载入失败关闭文档，可能删掉尚未恢复的未保存草稿 | 保留未应用草稿；旧异步响应必须核对标签对象，不能污染同 key 重新打开的标签；批量关闭及退出使用同一原则 |
| 迁移或跨项目移动后、首次同步前在系统中改名，条目 ID 与历史可能脱节 | 提交新路径时同时刷新新副本的物理身份；回归验证改名后仍保留原 ID、历史与属性 |
| 移动已提交但源文件清理失败或进程中断，旧副本重新出现在源项目 | 在提交事务中登记各来源的残留身份；连续 A→B→C 只清理本次来源标记；残留先改名再迁移也按身份重定位；保留原件 |
| 移动提交后原路径被同内容的新文件占用，清理会误删该新文件 | 除内容摘要外，同时复核源物理身份；不一致就保留文件并报告，新增提交后替换文件的确定性回归 |
| 复制导入截短合法长文件名，Markdown 图片相对引用失效 | 文件保留完整合法原名；不能按原名处理的目录明确报告，避免静默截短；冲突仍不覆盖已有文件 |
| 导入路径先去掉末尾空格，可能指向另一个文件 | 解析前验证原始名称，不能把不兼容的名称静默改成另一条路径；正常目录尾分隔符仍可使用 |
| 新项目载入期间切换视图，旧项目卡片重新显示 | 载入期间禁止使用旧列表重绘；新响应到达后按当前选定视图渲染 |
| 资源搜索词带入 SKILL 库、回收站等不同范围 | 跨功能区清空无关查询；返回工作台恢复原资源查询；直接点击资源分类同样隔离查询 |
| 设置无条件把 Windows 标成“稳定版”，甚至界面与后台版本不一致 | 仅显示平台、实际版本和构建；保留版本错配提示，稳定结论独立于平台标签 |

另修复一项测试可靠性问题：原生启动验收的合成后台改为与正式服务相同的 `ThreadingHTTPServer`，避免浏览器空闲预连接阻塞健康探测；失败时输出该临时实例的诊断日志。正式后台本来已使用多线程服务，没有放宽健康检查。

## 验证范围

- 最终冻结源码的后端全量复测：662 项，656 通过、6 跳过、0 失败，耗时 212.129 秒。跳过项为 1 项 macOS 专属原生调用和 5 项当前账户无创建符号链接权限的检查；没有将跳过项算作通过。
- 全部 65 个 `tests/frontend_*.cjs` 文件通过。包含编辑与草稿、Word 分页、媒体生命周期、搜索、项目库、导入、回收、迁移及增量更新；其中部分为 Node VM 合成状态测试，部分使用已有 Chromium 测试。
- `node --check frontend/app.js` 通过。
- Windows 原生 `desktop/build.py --test` 通过：核心 121、文件夹前台 10、截图 173、生命周期 44、增量安装桥接 21、快速阅览 63、缩放/音乐 13、启动/拖入桥接 19 项检查，另含单实例与固定 WebView 运行时检查。
- 新增隔离 HTTP 串联验收：编辑 → 改名 → 批量标签/状态 → 跨项目移动 → 回收恢复 → 过期保存冲突 → 中文搜索 → 全项目迁移 → 关闭服务并重启；核对正文 BOM/换行、属性、历史和保留的旧目录。
- 前端修复独立复核通过；数据与导入修复最终独立复核通过，修复前的两处确定性复现均被阻断。复核另明确：最后一次身份检查与按路径删除之间仍有很短的跨进程竞争窗口，不能将这组模拟验证等同于句柄级原子删除或真实断电验收。
- 发行白名单与个人绝对路径检查通过（944 个源文件）；本轮没有生成或发布新的完整发行包。

测试仅使用合成临时目录、独立端口和隔离数据。首次后端基线中，独立安装器测试因测试变量指向开发用 runtime 联接而失败；改为已验证的物理 runtime 路径后，该组 27 项通过，未放宽更新路径检查。

## 轻量化与性能

没有增加运行依赖、字体、模型、定时任务或全库内容散列。新的残留记录仅在跨项目移动的保护流程中产生，不给每个文件新增内容缓存。

10 万条合成索引、每次返回 60 条的查询结果：

| 操作 | P50 | P95 |
| --- | ---: | ---: |
| 普通列表 | 68.5 ms | 301.7 ms |
| 中文搜索 | 90.0 ms | 91.1 ms |
| 分类与状态筛选 | 40.1 ms | 42.5 ms |
| 按名称排序 | 67.0 ms | 72.0 ms |
| 按顺序排序 | 66.5 ms | 69.2 ms |
| 跳至第 90000 条 | 111.0 ms | 263.4 ms |

每项仅 5 次样本；普通列表首次测量有约 360 ms 的较高值。新进程首次列表 P50 67.8 ms，未清空系统文件缓存。全量交接导出约 10.53 秒，独立 Python 分配峰值约 1.45 MiB。上述不包含 UI 绘制、真实视频解码、完整进程内存或真正磁盘冷启动，不能据此宣称整机资源占用。

该合成数据库约 1.09 GiB，测试结束已自动清理；这不是新增安装包体积。此次仅下载锁定官方开发 SDK 9,259,926 字节（约 8.83 MiB），已校验 SHA-256，无新增用户运行依赖。

## 已知限制与稳定版门槛

1. 同一物理残留文件若被外部工具改成相同大小并主动恢复修改时间，轻量索引可能继续视为未改变。原文件保留，显式引用导入可以重新登记。本轮不增加反复读取大视频全文件的散列扫描；不能宣称所有外部内容变化都能自动识别。
2. 本轮未运行 macOS 原生复测，没有把 Windows 结果当作 Mac 验收。当前会话的交互式浏览器连接不可用；已有原生自动化通过，不等于完成真实中文输入法、多显示器/缩放组合或长期人工使用验收。
3. 本轮源码修复尚未安装到用户本机，也未上传为新发行包；原安装、素材、草稿及公开附件未覆盖。后续发行必须使用这些修复后的明确构建，完成最终包校验与平台复测，分别记录源码、本机与云端状态。

稳定性维护优先继续覆盖串联流程和异常恢复，不以增加功能数或测试数量替代整体可用性判断。
