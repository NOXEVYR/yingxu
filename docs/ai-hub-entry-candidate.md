# 曜核来源执行入口：独立源码候选

在原 AI 协作的工具调用区增加收起的“曜核来源执行（试用）”，沿用现有工作台、文字样式和选型，不新增 SDK、生成服务、模型或空闲轮询。代码只在本候选目录；没有替换本机、构建安装包或发布。

## 使用顺序

1. 展开入口，复制本机持久的来源身份。在曜核创建对应 `source` 私有授权；映序只保存该授权文件的位置和摘要，不把 token 写入数据库或公开接口。
2. 明确保存并检查来源。`source_read` 只用于回查，不得派单。授权绑定工作区、执行 authority/epoch 和连接修订；变化时需要明确重新核对，不能悄悄使用其他端口或工作端。
3. 选择原轮已保存的只读能力快照，填写 JSON 后“准备”。准备在同一数据库事务里保存不可变意图和绑定，不提交远端任务。
4. 单独点击“派单”。提交前先保存提交意图；丢失响应就保留未知状态，后续只“核对原请求”，不能自动重新生成。查询和取消均指向原绑定。
5. 远端成果描述保持只读。当前入口不下载远端媒体、不把 locator 当本地文件打开，不自动收件或审核。三方测试中的显式原轮收件通过原 `AIReceiptService` 完成；正式入口的工作端媒体传输和成果关联控件仍需下一阶段实现与界面验收。

## 边界和兼容

原 project/task/run/request 与输入摘要保持冻结。换页面后迟到的响应不得写入新轮。旧轮保留历史查询；旧轮提交与收件仍返回409。来源操作和执行操作同时进入更新、迁移及退出门禁；远端仍排队不会长期锁住本机退出。关闭只中止自己的短途 HTTP，不取消用户其他工具或重投未知任务。

来源授权读取最多16KiB，限制绝对本地普通文件，拒绝符号链接、重解析点、硬链接、UNC/ADS、重复 JSON 字段和越界类型；打开前、文件句柄和读后再次核对身份。Windows Python3.12重写文件后 `lstat/fstat.st_ctime_ns` 不一致，改用明确 creation time，并保留 dev/ino/size/mtime；POSIX仍检查ctime。祖先只比较身份，重复检查重解析点，允许无关临时文件改变目录时间。

Hub Bindings 复制件增加事务内准备入口，让意图与绑定一起提交；先前封存组件保持原样。原 direct-http 恢复、MCP七工具、项目/技能、字体和正文样式不变。入口当前最多展示48项绑定及48项待恢复记录，尚未增加完整历史分页。

## 验证范围

新增 Sources40项、入口服务/HTTP21项；实际封存Hub r2的产品服务TCP联调3项。真实无头浏览器验证16个默认收起、准备/派单分离、未知恢复、迟到响应、原轮保护与来源配置交互场景，并检查1280/760宽度。浏览器用合成API，不能代替原生Windows/Mac界面或模型验收。

全量后端及77个前端测试套件的最终结果、源码逐项摘要和三方固定Hub r3/棱光工作端的实际小图片结果见候选上级 `test-evidence` 与阶段报告。首次测试发现依赖环境/模拟Mac夹具问题；下一轮发现Windows授权时间误判；两轮失败证据保留，最终结果以源码摘要对应的清单为准。

## 继续推进

正式接入前需完成工作端成果传输的明确授权、原结果身份与本地文件关联、失败恢复和人工审核界面；真实模型调用另核对端口、凭据与成本。当前小图片验收使用 `EmptyImage→SaveImage`，只能证明调度、核验和收件，不证明视频/音乐/付费模型效果。不据此改正式版本号、下载页面或稳定版标识。
